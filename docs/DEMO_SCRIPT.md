# FocusLoop 演示视频脚本

目标时长：4 分 20 秒至 4 分 30 秒。最终视频必须控制在 5 分钟内。

## 0:00–0:25 问题与方案

“各位评委好，我是博丽灵梦赛高队的龚城立。很多学习计划中断在下一次复习。固定提醒只知道时间，无法判断用户此刻是否方便。FocusLoop 在 openvela 手表上接通内容输入、短时学习、主动回忆和再次触达；用户开启智能窗口后，手表还会寻找低压力、静止且临近到期的复习时机。”

画面：产品名、学习总览和五步流程。

## 0:25–1:00 语音创建计划

点击“语音输入”，说“学习数据库事务隔离级别”，再点击“完成语音”。

“QuickApp 通过 `system.velaclaw` 控制端侧 `ai_agent` 的录音和语音识别。识别文本成为学习主题，模型提取知识点并生成三选一短题。题目、解释、选项数量和答案索引通过本地检查后才会保存。”

画面：录音状态、识别后的主题、生成后的学习总览。

## 1:00–1:35 导入自己的材料

提前把示例 Markdown 推送到本地收件箱，在计划页点击“导入材料”。

“用户也可以提供文本或 Markdown。FocusLoop Skill 只读取固定收件箱，模型按知识点生成三到八张题卡，并为每张题卡保留一段材料依据。答题时，用户既能看解释，也能核对答案来自哪里。”

画面：导入状态、题卡数量、一道带“依据”的题目。

## 1:35–2:10 专注与主动回忆

进入专注页并直接完成，随后故意答错一道题。

“专注结束后手表振动并进入主动回忆。本地代码立即判分，答错后十分钟重试；连续答对后，间隔从一天、三天逐步增加，最长三十天。学习状态不依赖模型，应用重启后也能恢复。”

画面：计时、答题、解释与材料依据、下一次复习时间。

## 2:10–2:55 智能复习窗口

先展示默认关闭，再由用户开启。注入低压力和静止的模拟数据。

“智能推荐必须由用户主动开启。本地规则同时检查题卡到期、实时压力、连续加速度变化和三十分钟冷却期。条件满足时给出一次短时复习建议；高压力、运动中或数据不足时保持安静。用户选择‘开始复习’或‘稍后’后，系统会调整个人压力阈值并更新接受率。健康数据不进入模型。”

画面：开关、压力 18、静止、个人阈值、接受率，以及“开始复习 / 稍后”。画面注明“模拟数据”。

## 2:55–3:45 Agent 定时与主动拉起

完成一道题后点击“60 秒提醒”，退出应用，保留系统时间变化。

“下一次复习先写入本地待同步状态。Skill 用 `cron_list` 去重，再由 `cron_add` 创建一次性任务。时间到达后，`launch_quickapp` 主动打开 FocusLoop，首页识别到期词卡并显示‘立即复习’。短暂的 Agent 失败不会丢掉待同步任务。”

画面：安排成功、退出应用、时间变化、自动打开 FocusLoop。

## 3:45–4:10 异常恢复与工程证据

切换到未配置模型的环境，再创建一个计划。

“语音、健康接口或模型不可用时，各自能力会显示明确状态，内置题目继续支持专注、答题和进度保存。当前版本通过 26 项测试；连续 20 轮测试和 5 轮构建均无失败；生产依赖漏洞为零。”

画面：离线计划、测试结果、构建结果和 RPK。

## 4:10–4:25 收束

“FocusLoop 用模型整理学习内容，用手表判断当前场景，再由 openvela 执行下一次触达。我们要解决的，是让复习在需要而且方便的时候真正发生。谢谢各位评委。”

画面：产品名、团队名和智能复习窗口。

## 录制检查

- 语音链路提前配置 ASR，单独录制一次成功素材。
- 材料导入使用 `docs/samples/openvela-study-material.md`，提前推送到本地收件箱。
- 智能窗口使用大赛 miwear 健康镜像的 Mock 压力数据，画面标注“模拟数据”。
- 60 秒主动拉起保留开始、系统时间变化和自动打开应用三个证据点；中间等待可加速。
- 模型、健康接口和离线链路分别录制，后期按时间轴拼接。
- 使用 466×466 原始录屏，不裁掉状态文字；全片保留约 30 秒余量。
