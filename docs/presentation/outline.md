主线：复习中断往往发生在“下一次没有开始”。FocusLoop 把用户内容转成可核对的腕上短题，再结合记忆状态、设备情境和用户反馈选择下一次复习时机，最后由 openvela Agent 执行主动触达。

- openvela QuickApp + ai_agent Skill + 设备传感 + 持久定时

## Slide 2｜计划容易制定，下一次复习更容易中断

- 内容生成后，聊天助手通常不会继续执行后续学习动作
- 固定提醒只知道时间，不知道用户正在运动、压力较高，还是刚好有几十秒空闲
- 长材料难以直接放进 466×466 表盘
- 产品机会：手表贴身、交互短、能够读取设备状态，适合承接 30 秒级主动回忆
- 视觉：三条断点组成一条中断的流程；右侧用真实手表界面收束，不使用泛化人物插画

## Slide 3｜从内容输入到再次触达的五步流程

- 输入：语音主题、预设主题或本地文本 / Markdown
- 生成：Agent 提取知识点，生成问题、选项、解释和材料依据
- 专注：15 / 25 / 40 分钟单任务计时
- 回忆：本地判分，答错 10 分钟重试，连续答对逐步拉长间隔
- 再次触达：时间型提醒持久执行；可选智能窗口寻找低打扰时机
- 视觉：横向五步流程，下半部分放真实四状态 UI 总览
- 素材：`docs/screenshots/focusloop-overview.png`

## Slide 4｜五层协同，让模型、设备和系统各自可独立降级

- 输入层：PTT/ASR、本地材料收件箱
- 模型层：知识提取、题卡生成、受控工具调用
- 本地层：结构校验、判分、复习间隔、状态恢复
- 情境层：压力、加速度、到期时间、冷却期和用户反馈
- 执行层：`cron_add` 持久定时，`launch_quickapp` 主动拉起
- 边界：模型不可用时保留离线题目；健康接口不可用时只关闭智能窗口
- 视觉：五层水平管线；下方用两条降级路径说明故障隔离

## Slide 5｜创新一：把个人材料变成可核对的知识题卡

- 语音用于快速给出主题；文本或 Markdown 提供完整材料
- 模型先拆分知识点，再为每个知识点生成问题、正确答案、干扰项、解释和简短原文依据
- `focusloop-json` 结果经过字段、长度、三选项、答案索引检查后才进入学习状态
- 导入 Skill 只读取固定本地收件箱，材料不能改变工具权限或操作类型
- 答题页同时展示解释和“依据”，评委可以当场核对生成内容来自哪里
- 领先点：把自由文本生成压缩成“有来源、可校验、能持续调度”的腕上学习单元
- 视觉：左侧材料原文，中间知识点提取，右侧放大一张“问题 + 解释 + 依据”真实题卡
- 素材：
  - `docs/screenshots/focusloop-smart-overview.png`
  - `docs/screenshots/focusloop-goldfish-quiz-result.png`

## Slide 6｜创新二：记忆到期后，再判断此刻是否适合打扰

- 功能默认关闭，用户主动开启后才订阅压力和加速度
- 同时满足：已有学习记录、30 分钟内到期、压力低、连续静止、冷却结束
- 高压力、运动中、数据不足或尚未到期时保持安静
- 用户选择“开始复习”或“稍后”，本地用 80/20 平滑调整个人阈值，并显示接受率
- 健康数据只在本地参与时机判断，不进入模型
- 领先点：把记忆调度与情境判断拆成两层，再用显式反馈做个人化调整
- 视觉：中央放智能窗口真实 UI；四周连接记忆、压力、活动、冷却；右侧放“开始 / 稍后 → 阈值更新”反馈环
